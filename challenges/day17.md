## 📅 Day 17: PostgreSQL 데이터베이스 유저 생성 및 권한 배포

### 1. Task

- **요구사항**: Nautilus 애플리케이션 개발 팀의 신규 서비스 배포에 따른 사전 필수 인프라 작업을 위해, Stratos DC 내 가동 중인 데이터베이스 호스트에 신규 PostgreSQL 데이터베이스 및 전용 접근 유저를 생성하고 무결한 수준의 권한 바인딩을 완료한다.

- **목표**:
  1. PostgreSQL 대화형 터미널(`psql`)을 통한 실시간 데이터베이스 관리자 세션 진입
  2. 요구사항에 명시된 신규 유저(`kodekloud_cap`) 생성 및 암호 복잡성 정책(`BruCStnMT5`) 적용
  3. 신규 프로독션 데이터베이스(`kodekloud_db6`) 개설
  4. 데이터베이스 보안 및 무결성 확보를 위해 해당 데이터베이스에 대한 모든 권한(`GRANT ALL PRIVILEGES`)을 생성된 전용 유저에게 위임
  5. 서비스 중단 없는 아키텍처 가용성을 위해 PostgreSQL 데몬 재시작 없이 쿼리 구문 실시간 처리

### 2. Workflow

```text
[ 점프 호스트 ] ---> [ stdb01 (Database 호스트) ] ---> [ postgres 관리자 유저 스위칭 ]
                                                                   |
                                                                   v
[ 권한 위임 (GRANT) ] <--- [ DB 생성 (CREATE) ] <--- [ 유저 생성 (CREATE USER) ]

```

### 3. 해결 과정 (Action)

#### 3-1. 데이터베이스 노드 접근 및 관리자 컨텍스트 전환

인프라 제어의 보안 무결성을 보장하기 위해 대상 호스트에 원격 권한 계정으로 진입 후, PostgreSQL 기본 시스템 계정으로 실행 컨텍스트를 스위칭한다.

```bash
# 1. 점프 호스트에서 Nautilus 데이터베이스 호스트 원격 접속
ssh peter@stdb01

# 2. 루트 권한 획득 후 PostgreSQL 최고 관리자 시스템 유저 계정으로 전환
sudo su - postgres

```

#### 3-2. psql 인스턴스 접속 및 쿼리 제어 개시

서비스 가동 중단(Downtime)을 방지하기 위해 서비스 재시작 명령을 전면 배제하고, 실시간 스트리밍 대화형 터미널 쉘에 진입하여 구조적 질의어(SQL)를 통해 개체를 선언한다.

```bash
# 1. PostgreSQL 대화형 실행 쉘 엔진 구동
psql
# 시스템 출력 확인: psql (13.23) Type "help" for help.

# 2. 명시된 복잡성 패스워드를 주입하여 고유 유저 롤(Role) 선언
CREATE USER kodekloud_cap WITH PASSWORD 'BruCStnMT5';
# 결과 반환: CREATE ROLE

# 3. 신규 애플리케이션 수용을 위한 격리된 데이터베이스 스키마 인스턴스 생성
CREATE DATABASE kodekloud_db6;
# 결과 반환: CREATE DATABASE

# 4. 데이터 원격 제어 권한 무결성 보장을 위해 전 권한을 해당 롤에 바인딩
GRANT ALL PRIVILEGES ON DATABASE kodekloud_db6 TO kodekloud_cap;
# 결과 반환: GRANT

# 5. 인스턴스 내부 쉘 안전 종료 및 세션 원복
\q
exit
exit

```

### 4. 무엇을 배웠는가 (Takeaway)

- **PostgreSQL 롤(Role)과 데이터베이스 보안 아키텍처**: 데이터베이스에서 유저를 생성하고 권한을 쪼개는 것은 '회사의 신입 사원에게 전용 출입증과 개인 책상을 만들어주는 것'과 같다. 만약 모든 애플리케이션이 최고 관리자(`postgres`) 계정으로 데이터베이스를 마구잡이로 헤집고 다니면 보안 사고 발생 시 인프라 무결성이 완전히 붕괴된다. 실무 인프라 관점에서는 서비스별로 전용 유저 계정을 파고 해당 서비스가 사용할 전용 데이터베이스 인스턴스에만 접근할 수 있도록 권한의 범위를 명확히 제한하는 최소 권한의 법칙(Principle of Least Privilege) 설계가 필수적이다.

- **실시간 데이터베이스 쿼리 제어와 제약 조건(No Restart)**: 실행 중인 데이터베이스 서비스를 재시작하지 않고 내부 질의어로 개체를 생성하는 것은 '달리는 자동차의 엔진을 끄지 않고 조수석 시트를 교체하는 것'과 같다. 엔터프라이즈 실무 인프라 환경에서 DB 데몬의 재시작은 연결된 모든 애플리케이션의 세션을 끊어버리는 심각한 장애(Downtime)를 유발하므로, `psql` 같은 대화형 터미널을 활용해 런타임 상태에서 쿼리를 즉각적으로 주입하여 무중단 상태로 인프라 요구사항을 유연하게 반영하는 능력이 대단히 중요하다.
