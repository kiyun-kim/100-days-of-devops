## 📅 Day 18: MariaDB 패키지 설치 및 신규 데이터베이스·유저 권한 배포

### 1. Task

- **요구사항**: Stratos 데이터 센터의 인프라 확장 계획에 따라, 대기 중인 데이터베이스 호스트에 관계형 데이터베이스 관리 시스템(RDBMS)인 MariaDB를 수동 설치하고 신규 서비스용 데이터베이스 환경 및 전용 접근 유저를 안전하게 개설합니다.

- **목표**:

1. `stdb01` 데이터베이스 호스트 내 `mariadb-server` 패키지 설치 및 시스템 데몬 활성화
2. 신규 서비스 수용을 위한 독립 데이터베이스(`kodekloud_db2`) 인스턴스 생성
3. 보안 복잡성을 만족하는 계정(`kodekloud_roy` / `Rc5C9EyvbU`) 생성 및 호스트 접근 제어 정의
4. 데이터베이스 보안 무결성 확보를 위해 생성된 유저에게 타겟 DB의 모든 권한(`GRANT ALL PRIVILEGES`) 위임 및 즉시 반영

### 2. Workflow

```text
[ 점프 호스트 ] ---> [ stdb01 호스트 접속 ] ---> [ mariadb-server 수동 설치 및 기동 ]
                                                                   |
                                                                   v
[ 런타임 권한 반영 ] <--- [ 권한 위임 (GRANT) ] <--- [ 유저 생성 ] <--- [ DB 생성 ]

```

### 3. 해결 과정 (Action)

#### 3-1. 데이터베이스 엔진 설치 및 초기 인프라 가동

```bash
# 1. 점프 호스트에서 데이터베이스 전용 노드 원격 접속
ssh peter@stdb01

# 2. 패키지 관리자를 통해 MariaDB 서버 엔진 설치
sudo yum install -y mariadb-server

# 3. 데이터베이스 시스템 서비스 가동 및 서버 부팅 시 자동 시작 등록
sudo systemctl start mariadb
sudo systemctl enable mariadb

# 4. 관리자 권한으로 MariaDB 내부 대화형 콘솔 쉘 진입
sudo mysql

```

#### 3-2. 데이터베이스 개체 선언 및 보안 권한 부여 (SQL 실행)

```sql
-- 1. 격리된 신규 데이터베이스 스키마 생성
CREATE DATABASE kodekloud_db2;

-- 2. 고유 계정 생성 및 암호 정책 바인딩
CREATE USER 'kodekloud_roy'@'localhost' IDENTIFIED BY 'Rc5C9EyvbU';

-- 3. 생성된 데이터베이스의 모든 제어 권한을 해당 유저에게 위임
GRANT ALL PRIVILEGES ON kodekloud_db2.* TO 'kodekloud_roy'@'localhost';

-- 4. 변경된 권한 테이블을 메모리에 즉시 동기화 및 쉘 종료
FLUSH PRIVILEGES;
EXIT;

```

### 4. 핵심 쿼리문 상세 해설 (Step 3-2 톺아보기)

엔터프라이즈 데이터베이스 인프라 세팅 시 백엔드 및 DevOps 엔지니어가 반드시 숙지해야 하는 핵심 SQL 구문의 상세 동작 매커니즘은 다음과 같습니다.

#### 📌 CREATE USER 'kodekloud_roy'@'localhost' IDENTIFIED BY 'Rc5C9EyvbU';

- **개념 정의**: 데이터베이스 시스템에 접근할 수 있는 **새로운 독점 로그인 계정을 안전하게 개설**하는 명령입니다.
- **상세 원리**: `'kodekloud_roy'`는 생성할 유저의 고유 ID이며, 뒤에 붙은 `'@'localhost'`는 "이 유저는 오직 이 데이터베이스가 돌아가고 있는 서버 본체(내부 로컬 환경) 안에서만 접속할 수 있다"는 강력한 네트워크 접근 제어 정책입니다. 외부 해커가 원격으로 이 계정을 도용하여 인프라 외곽에서 로그인하는 것을 원천 차단하며, `IDENTIFIED BY` 뒤에 오는 보안 복잡성이 높은 문자열을 해시 암호화하여 계정 비밀번호로 바인딩합니다.

#### 📌 GRANT ALL PRIVILEGES ON kodekloud_db2.\* TO 'kodekloud_roy'@'localhost';

- **개념 정의**: 생성된 특정 유저에게 해당 데이터베이스를 자유롭게 제어할 수 있는 **'마스터키(전권)'를 부여**하는 명령입니다.
- **상세 원리**: `GRANT ALL PRIVILEGES`는 데이터의 조회(`SELECT`), 삽입(`INSERT`), 수정(`UPDATE`), 삭제(`DELETE`) 및 테이블 구조 변경까지 일체의 행정 권한을 부여하겠다는 의미입니다. 가장 중요한 부분은 `ON kodekloud_db2.*` 컨텍스트인데, 이는 "오직 `kodekloud_db2`라는 데이터베이스 내부에 속한 모든 데이터 테이블(`*`)에 대해서만 권한을 허용한다"는 뜻입니다. 다른 운영 환경의 핵심 데이터베이스에는 일절 손대지 못하도록 논리적 격리벽을 세우는 보안 아키텍처 설계의 필수 메커니즘입니다.

#### 📌 FLUSH PRIVILEGES;

- **개념 정의**: 방금 설정한 유저 생성 및 권한 부여 정보를 데이터베이스 시스템에 즉시 새로고침(실시간 동기화)하라는 명령입니다.
- **상세 원리**: MariaDB는 고속 연산 및 빈번한 보안 검증을 위해 유저의 권한 테이블 정보를 메모리(RAM)에 캐시(Cache) 형태로 올려두고 관리합니다. `GRANT` 구문이 실행되었을 때 메모리 갱신 지연으로 인해 간혹 유저가 즉시 접속하지 못하는 일시적 정체 현상이 발생할 수 있습니다. 이 명령어를 명시적으로 실행해 줌으로써 "메모리에 상주하는 이전 권한 캐시를 파기하고, 디스크에 새로 기록된 권한 테이블 정보를 즉시 다시 읽어와 동기화하라"고 지시하여 인프라 설정의 즉각적인 영속성을 보장합니다.

### 5. 무엇을 배웠는가 (Takeaway)

- **최소 권한의 법칙과 데이터베이스 격리**: 인프라 설계 시 모든 애플리케이션이 최고 관리자(`root`) 계정으로 데이터베이스에 접근하게 되면 싱글 포인트 오브 페일러(SPoF) 및 심각한 보안 유실이 발생합니다. 각 서비스 목적에 맞는 독립 데이터베이스를 파고, 로컬 접근 권한만 부여된 격리 계정을 연결해 줌으로써 침해 사고 발생 시 피해 규모를 최소화하는 능력을 배양했습니다.

- **MariaDB 인프라 라이프사이클 핸들링**: 리눅스 패키지 매니저(`yum`)를 이용한 데이터베이스 엔진의 수동 설치부터, 데몬 프로세스의 영속 가동(`systemctl enable`), 그리고 내부 런타임 시스템 설정 및 권한 동기화까지의 엔드투엔드 백엔드 인프라 파이프라인 관리 흐름을 완벽히 이해할 수 있었습니다.
