## 📅 Day 19: Apache 가속 정적 웹사이트 배포 및 원격 데이터 마이그레이션

### 1. Task

- **요구사항**: xFusionCorp Industries의 신규 정적 웹사이트 인프라 호스팅 준비를 위해, Stratos 데이터 센터의 웹 애플리케이션 호스트에 고성능 정적 아키텍처를 수동 빌드하고 개발 서버의 백업 볼륨 트래픽을 안전하게 마이그레이션합니다.

- **목표**:
  1. `stapp03` 호스트에 `httpd` 패키지 및 종속성 컴포넌트 설치 및 기동을 완료합니다.
  2. 아파치 기본 가동 웹 포트를 표준 `80` 포트에서 커스텀 보안 포트인 `6000` 포트로 변경합니다.
  3. 점프 호스트 내 로컬에 보관 중인 웹사이트 정적 백업 리소스 디렉토리(`media`, `games`)를 원격 스토리지 인프라로 손실 없이 이주합니다.
  4. 웹 루트 하부 경로 매핑을 완료하고, 호스트 내부에서 `curl` 통신을 제어하여 부하분산 정적 라우팅 환경을 최종 검증합니다.

### 2. Workflow

```text
[ 점프 호스트 (Backup 데이터) ] --- (SCP 원격 전송) ---> [ App Server 3 (/tmp 경로) ]
                                                                   |
                                                                   v
[ 6000번 포트 최종 검증 ] <--- [ Apache 재시작 ] <--- [ 웹 루트(/var/www/html) 이동 ]

```

### 3. 해결 과정 (Action)

#### 3-1. 원격 보안 프로토콜을 이용한 자산 이주 및 패키지 셋업

```bash
# 1. 점프 호스트 내부의 정적 미디어 백업 디렉토리를 암호화 채널을 통해 원격 서버로 전송
scp -r /home/thor/media banner@stapp03:/tmp/
scp -r /home/thor/games banner@stapp03:/tmp/

# 2. App Server 3 노드 보안 쉘 접속 및 웹 인프라 패키지 가동
ssh banner@stapp03
sudo yum install -y httpd
sudo systemctl start httpd && sudo systemctl enable httpd

```

#### 3-2. 포트 포워딩 인프라 제어 및 데이터 루트 배치

```bash
# 1. 아파치 기본 메인 설정 파일 수동 제어
sudo vi /etc/httpd/conf/httpd.conf
# (Listen 80 파트를 찾아 커스텀 수신 환경인 'Listen 6000'으로 환경 변수 변경)

# 2. 임시 캐시 디렉토리(/tmp)에 수신된 백업 자산을 공식 웹 도큐먼트 루트로 구조 조정
sudo mv /tmp/media /var/www/html/
sudo mv /tmp/games /var/www/html/

# 3. Apache 아키텍처 환경 설정 파일의 무결성 검증 및 데몬 재기동
sudo httpd -t
sudo systemctl restart httpd

```

#### 3-3. 로컬 가용성 런타임 엔드포인트 검증

```bash
# 엔드포인트 1 번 라우팅 통신 무결성 검사
curl http://localhost:6000/media/

# 엔드포인트 2 번 라우팅 통신 무결성 검사
curl http://localhost:6000/games/
# 시스템 응답: HTTP/1.1 200 OK 또는 301 리다이렉트 소스 코드 표출 확인 (검증 완료)

```

### 4. 무엇을 배웠는가 (Takeaway)

주니어 인프라 엔지니어가 대규모 데이터 이주 및 웹 서비스를 배포할 때 반드시 체득해야 하는 코어 메커니즘입니다.

#### 📌 1. SCP (Secure Copy Protocol)의 본질과 매커니즘

- **개념 정의**: 네트워크를 통해 로컬 호스트와 원격 호스트 간에 **파일을 안전하게 주고받는 암호화 전송 프로토콜**입니다.

- **상세 원리**: 전통적인 파일 전송 방식인 FTP는 데이터를 평문으로 전송하여 스니핑(암호 탈취) 보안 사고에 무방비로 노출됩니다. 반면 SCP는 전 세계 인프라의 표준 보안 연결인 **SSH(Secure Shell) 엔진의 암호화 터널링 기술을 그대로 차용**합니다. 즉, 데이터를 보내기 전 강력한 대칭키 암호화 가방에 패킷을 쑤셔 넣은 뒤 전송하므로, 중간 네트워크 회선을 해커가 가로채더라도 파일의 실체적 내용을 절대 볼 수 없도록 설계된 고보안성 자산 이주 프로토콜입니다. 옵션으로 사용된 `-r` 키워드는 하위 폴더 구조 전체를 재귀적(Recursive)으로 일괄 복사하겠다는 의미입니다.

#### 📌 2. 아파치 가상 디렉토리 라우팅과 다중 웹 가동의 원리

- **개념 정의**: 단 하나의 웹 서버 엔진(`Listen 6000`) 환경 하에서 **어떻게 `/media`와 `/games`라는 2개의 서비스 주소가 충돌 없이 독립 작동하는가**에 대한 아키텍처 원리입니다.

- **상세 원리**: Apache 웹 서버는 설정 파일 내부에 명시된 `DocumentRoot` (기본 경로: `/var/www/html`) 디렉토리를 베이스 기점으로 삼아 세상을 바라봅니다. 웹 서버 정문에 해당하는 `6000`번 포트로 사용자가 요청을 보내면, Apache 엔진은 URL의 뒤쪽 꼬리표(컨텍스트 패스)를 분석합니다.
- 사용자가 `http://localhost:6000/media/`로 접근하면, 엔진은 자동으로 리눅스 파일 시스템의 물리 경로인 `/var/www/html/media/`로 진입하여 내부의 `index.html` 파일을 서빙합니다.
- 사용자가 `http://localhost:6000/games/`로 접근하면, 동일한 베이스 라인 하위의 다른 물리 디렉토리인 `/var/www/html/games/` 경로로 세션을 유연하게 분기합니다.
- 결과적으로, 단 하나의 아파치 프로세스가 구동 중이더라도 시스템 내부의 폴더 격리 트리 구조(Tree Structure)를 통해 수백 수천 개의 독립된 서브 웹 서비스 및 정적 파일 가속 환경을 단일 포트 내에서 자원 효율적으로 다중 배포할 수 있게 되는 것입니다.

#### 📌 3. 포트 커스터마이징을 통한 보안 아키텍처 강화

- 인프라 보안 관리 관점에서 널리 알려진 공용 웹 포트(80, 443)를 그대로 사용하는 것은 자동화된 악성 봇이나 스캔 공격의 1차 타깃이 될 수 있습니다. 아파치의 핵심 지시자인 Listen 지시문을 수정하여 커스텀 포트(6000)로 우회 가동해 봄으로써, 포트 은닉화를 통한 서비스 1차 방어벽 구축 방법을 체득하였습니다.
