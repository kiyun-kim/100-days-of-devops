## 📅 Day 21: Storage 서버 내 중앙 집중형 Git Bare 저장소 구축 및 환경 설정

### 1. Task

- **요구사항**: Nautilus 개발 팀의 신규 애플리케이션 개발 프로젝트에 대응하기 위해, 분산 버전 관리 시스템의 중앙 원격 저장소 역할을 수행할 Git 환경을 Stratos DC 내부의 Storage 서버에 안정적으로 구축하고 초기화합니다.

- **목표**:

1. Storage 서버에 접속하여 패키지 관리자(`yum`)를 통해 `git` 패키지를 설치합니다.
2. `/opt/official.git` 경로에 작업 디렉토리가 없는 순수 소스 코드 저장 용도의 베어 저장소(Bare Repository)를 정확한 명칭으로 생성합니다.

---

### 2. Workflow

```text
+-----------------------+                     +------------------------------------+
|  Jump Host (Terminal) | -- (SSH 접속) ----> |        Storage Server              |
|                       |                     |  - Git 패키지 설치 (yum)           |
|                       |                     |  - /opt/official.git (Bare 생성)   |
+-----------------------+                     +------------------------------------+

```

---

### 3. 해결 과정 (Action)

#### 3-1. Storage 서버 접속 및 패키지 설치

우선 인프라 구조상 점프 호스트에서 Storage 서버로 SSH 접속을 진행한 뒤, 시스템 패키지 업데이트 및 Git 바이너리를 설치합니다.

```bash
# 점프 호스트에서 Storage 서버로 접속합니다. (인프라 환경 정보에 따른 계정 및 호스트명 적용)
ssh natasha@ststorage01

# 관리자 권한을 획득하거나 sudo를 활용하여 yum 패키지 관리자로 git을 설치합니다.
sudo yum install -y git

# 설치가 정상적으로 완료되었는지 버전을 체크하여 검증합니다.
git --version

```

#### 3-2. Git 베어(Bare) 저장소 생성 및 경로 설정

개발자들이 푸시(Push)할 수 있는 순수 저장소 용도의 디렉토리를 생성하고 Git 초기화 작업을 수행합니다.

```bash
# root 권한 또는 적절한 쓰기 권한이 있는 상태에서 /opt 경로로 이동합니다.
cd /opt

# 지정된 명칭의 베어 저장소를 초기화합니다.
# --bare 옵션은 작업 폴더(.git 내부 파일들이 꺼내져 있는 형태) 없이 이력 관리 데이터만 저장하도록 합니다.
sudo git init --bare official.git

# 생성된 저장소의 디렉토리 구조와 소유권 상태를 확인합니다.
ls -l /opt/official.git

```

---

### 4. 핵심 개념 정리

• **베어 저장소 (Bare Repository)**: 워킹 디렉토리(Working Directory)가 존재하지 않고, `.git` 폴더 내부의 형상 관리 및 커밋 히스토리 데이터만을 가지는 격리된 형태의 저장소입니다. 주로 개발자들이 직접 코드를 수정하는 공간이 아닌, 변경 사항을 밀어 넣고(Push) 가져오는(Pull) 중앙 원격 서버의 역할을 수행할 때 사용됩니다.

💡 **비유하자면** 일반 저장소가 "요리사가 직접 칼질을 하고 재료를 다듬는 주방 작업대"라면, 베어 저장소는 "오직 완성된 밀키트와 레시피 북만 안전하게 보관하고 입출고를 관리하는 중앙 물류 창고"와 같습니다. 창고 안에서는 직접 요리(코드 수정)를 하지 않고 오로지 보관과 유통만 담당합니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

• **원점(명세서) 검증의 중요성**: 파일명이나 디렉토리 경로 뒤에 붙는 `.git`과 같은 확장자는 단순 관례를 넘어 협업 인프라 전체의 네이밍 컨벤션을 결정짓는 핵심 요소입니다. 명세에 명시된 명칭인 `/opt/official.git`을 오타 없이 완벽하게 생성함으로써 사소한 휴먼 에러가 전체 파이프라인의 연동 실패로 이어지는 것을 방지하는 정밀함을 길렀습니다.

• **역할에 따른 격리(Isolate) 설계**: 서버 내부에서 애플리케이션을 직접 실행하거나 빌드하는 환경이 아니라면, 작업 디렉토리가 포함된 일반 Git 저장소는 불필요한 디스크 공간을 차지하고 동시 Push 시 충돌(Conflict)을 유발할 수 있습니다. 운영 환경의 목적에 맞춰 'Bare'라는 격리된 형태의 기술셋을 올바르게 선택하고 구성하는 아키텍처적 안목의 중요성을 체득하였습니다.
