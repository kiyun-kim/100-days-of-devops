## 📅 Day 22: Storage Server에서 Git 저장소 복제

### 1. Task

- **요구사항**: DevOps 팀이 구축했으나 사용되지 않고 있는 원격 Git 저장소를 Nautilus 개발 팀의 요구사항에 맞춰 Stratos DC 내 Storage 서버(`ststor01`)의 지정된 경로로 복제하여 형상 관리 환경을 마이그레이션합니다.

- **목표**:
  1. Storage 서버에 `natasha` 사용자로 안전하게 원격 접속합니다.
  2. 동적으로 지정된 원격 Git 저장소(타겟: `/opt/ecommerce.git`)를 `/usr/src/kodekloudrepos` 경로로 복제합니다.
  3. 대상 루트 디렉토리에 정확한 권한 구조를 생성합니다.

---

### 2. Workflow

```text
+-----------------------+                    +-------------------------------------------------------+
|  Jump Host (Terminal) | -- (SSH 접속) ---> |                    StorageServer                      |
|                       |                    |  - 동적 저장소: /opt/ecommerce.git                    |
|                       |                    |  - 대상 디렉토리: /usr/src/kodekloudrepos             |
|                       |                    |  - 구조 해결: [git clone] 후 상위 경로 [git init]     |
+-----------------------+                    +-------------------------------------------------------+

```

---

### 3. 해결 과정 (Action)

#### 3-1. Storage 서버 원격 접속 및 대상 경로 이동

점프 호스트 관문에서 `natasha` 계정을 이용해 Storage 서버로 우회 접속한 후, 배포 대상지로 할당된 경로로 이동합니다.

```bash
# Jump 호스트에서 Storage 서버로 natasha 계정을 통해 SSH 접속합니다.
ssh natasha@ststor01

# 배포 및 복제 대상 디렉토리로 이동합니다.
cd /usr/src/kodekloudrepos/

```

#### 3-2. 원격 저장소 복제 및 최상위 형상 관리 구조 활성화 (`git init`)

```bash
# 1. 원격 저장소를 하위 폴더로 1차 복제합니다.
git clone /opt/ecommerce.git

# 2. 최상위 루트(/usr/src/kodekloudrepos/)에 .git 폴더를 위치시키기 위해 해당 경로에서 직접 Git 저장소를 수동 초기화합니다.
git init

# 3. 최상위 경로에 natasha 소유의 .git 구조가 정상 생성되었는지 최종 형태를 검증합니다.
git status

```

---

### 4. 핵심 개념 정리

- **Git 초기화 (Git Init)**: 새로운 Git 저장소를 로컬 환경에 생성하거나 기존 디렉토리를 버전 관리 대상 폴더로 전환할 때 사용하는 명령어입니다. 이 명령을 수행하면 디렉토리 내부에 형상 관리 이력과 인덱스 메타데이터를 담는 격리된 `.git` 숨김 폴더가 생성됩니다.

💡 **비유하자면** `git clone`이 "외부에 있는 기성품 보관함(폴더)을 통째로 배송받아 마당에 내려놓는 것"이라면, `git init`은 "현재 내가 서 있는 방(현재 디렉토리) 자체를 공식적인 관인 영수증 보관소(.git)로 즉시 지정해 버리는 것"과 같습니다. 이로 인해 방의 구조적 입지(경로 기준)가 시스템상에서 공식 인증을 받게 됩니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

- **Git 데이터 구조와 디렉토리 계층 이해**: 일반적인 `git clone` 명령어 실행 시 원격 저장소 이름으로 하위 디렉토리가 자동 생성되는 특성을 파악하고, 이로 인해 발생할 수 있는 경로 깊이(Depth)의 불일치 문제를 구조적으로 분석하는 안목을 길렀습니다.

- **`git init` 명령어의 핵심 역할 환기**: 단순히 새로운 프로젝트를 시작할 때만 `git init`을 사용하는 것을 넘어, 특정 특정 타겟 디렉토리를 명확한 형상 관리 루트(Root) 파일 시스템 구조로 명시하고 독립적인 버전 관리 공간으로 제어할 수 있는 `git init`의 본질적인 동작 원리와 역할을 다시 한번 깊이 있게 학습할 수 있었습니다.
