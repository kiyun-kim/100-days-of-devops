## 📅 Day 22: Git 저장소 Fork

### 1. Task

- **요구사항**: Nautilus 프로젝트 팀에 새로 합류한 신규 개발자 `jon`이 소스 코드 분석 및 개별 개발 작업을 시작할 수 있도록, 원본 원격 저장소를 본인의 개인 계정 공간으로 안전하게 포크(Fork)합니다.

- **목표**:

1. Gitea 웹 인터페이스에 제공된 개발자 계정(`jon` / `Jon_pass123`)으로 로그인합니다.
2. 원본 저장소인 `sarah/story-blog`를 탐색하여 `jon` 계정 하위로 복사본(Fork)을 생성합니다.

---

### 2. Workflow

```text
[Gitea Web UI 로그인] -> [sarah/story-blog 저장소 이동] -> [우측 상단 '포크' 클릭] -> [jon/story-blog 생성 완료]

```

---

### 3. 해결 과정 (Action)

#### 3-1. Gitea 로그인 및 저장소 포크

본 미션은 터미널 커맨드가 아닌 Gitea 웹 브라우저 콘솔을 통해 수행되었습니다.

1. **Gitea UI 접속 및 인증**: 상단 바의 Gitea UI 탭을 열고, 사용자 이름 `jon`과 패스워드 `Jon_pass123`을 입력하여 세션을 활성화했습니다.

2. **저장소 탐색 및 분기**: `sarah/story-blog` 프로젝트 페이지로 이동한 뒤, 우측 상단의 **Fork** 버튼을 클릭하여 `jon/story-blog`로의 복제를 단행했습니다.

---

### 4. 핵심 개념 정리

- **포크 (Fork)**: 다른 사람의 원격 Git 저장소를 자신의 계정 프로필 하위로 그대로 복사하여, 원본 프로젝트에 영향을 주지 않고 자유롭게 소스 코드를 수정 및 실험할 수 있게 만드는 기능입니다.

💡 **비유하자면**, 유명 맛집의 "비법 레시피 북(원본 저장소)"을 그대로 복사기로 복사해서 "내 개인 요리 연구실 책상(내 계정)"으로 가져오는 것과 같습니다. 이제 내 맘대로 레시피를 수정하고 요리해도 원본 맛집의 레시피는 전혀 훼손되지 않습니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

- **오픈소스 협업 워크플로우의 이해**: 중앙 저장소에 직접 권한을 부여받지 않더라도, `Fork`와 `Pull Request` 메커니즘을 통해 대규모 인원이 안전하고 독립적으로 소스 코드를 분기하고 기여할 수 있는 최신 DevOps 협업 아키텍처의 기본 소양을 체득했습니다.
