## 📅 Day 24: Storage 서버 내 Git 저장소 신규 브랜치 생성 및 소유권 보안 제어

### 1. Task

- **요구사항**: Nautilus 개발 팀이 소스 코드를 관리 중인 Storage 서버 내부의 특정 로컬 저장소에서 안전하게 신규 애플리케이션 Feature를 개발할 수 있도록, 원본 소스 코드 훼손 없이 독립적인 분기 브랜치를 생성하고 전환합니다.

- **목표**:
  1. Storage 서버(`ststor01`)의 `/usr/src/kodekloudrepos/demo` 저장소로 이동합니다.
  2. 기존 `master` 브랜치를 기반으로 `xfusioncorp_demo`라는 명칭의 신규 브랜치를 정확히 생성합니다.
  3. 작업 도중 기존 소스 코드 파일에 어떠한 변경 사항도 발생시키지 않습니다.

---

### 2. Workflow

```text
+----------------------------------+
|   /usr/src/kodekloudrepos/demo   |
|      (소유자: 관리자 권한)       |
+----------------------------------+
                 |
                 v [일반 계정 접근 차단: dubious ownership 경고 발생]
+----------------------------------+
|    sudo 권한을 통한 보안 우회    |
| git checkout -b xfusioncorp_demo |
+----------------------------------+

```

---

### 3. 해결 과정 (Action)

#### 3-1. Storage 서버 접속 및 대상 경로 이동

점프 호스트에서 Storage 서버로 원격 접속을 단행한 뒤, 형상 관리를 수행할 대상 디렉토리로 이동합니다.

```bash
# Storage 서버에 natasha 계정으로 원격 연결합니다.
ssh natasha@ststor01

# 형상 관리 대상 로컬 Git 저장소 디렉토리로 이동합니다.
cd /usr/src/kodekloudrepos/demo

```

#### 3-2. 다중 사용자 보안 제어 우회 및 브랜치 생성/전환

디렉토리 소유권 불일치로 인한 Git의 내부 보안 차단 정책을 `sudo` 바이너리 권한 상승을 통해 해결하고 지정된 브랜치를 안전하게 배포합니다.

```bash
# 1. 일반 계정으로 브랜치 전환 시 다중 사용자 소유권 경고(dubious ownership)가 발생하므로
# 최고 관리자 권한(sudo)을 부여하여 master 브랜치로부터 xfusioncorp_demo 브랜치를 생성하고 즉시 전환합니다.
sudo git checkout -b xfusioncorp_demo

# 2. 작업 브랜치가 정상적으로 분기되었는지 형상 관리 상태를 최종 검증합니다.
sudo git status

```

---

#### 💡 왜 일반 계정으로 안 되고 `sudo`를 써야만 했을까요?

Git은 **v2.35.2 업데이트 이후** 다중 사용자 환경에서의 보안 취약점(CVE-2022-24765)을 방어하기 위해 엄청나게 엄격한 보안 매커니즘을 도입했습니다.

- **원인**: 현재 로그인한 계정은 `natasha`이지만, 대상 저장소 폴더(`/usr/src/kodekloudrepos/demo`)의 실제 파일 시스템 소유자는 `root` 또는 다른 관리자 계정으로 지정되어 있습니다.
- **Git의 방어 기제**: Git은 현재 실행하는 유저(`natasha`)와 폴더의 소유자가 다르면, 악성 사용자가 공유 폴더에 심어둔 설정 파일(`.git/config`)을 통해 권한 상승 공격을 감행할 수 있다고 판단하여 명령어를 강제로 차단(`dubious ownership`)합니다.
- **`sudo`의 역할**: 명령어 앞에 `sudo`를 붙이게 되면 최고 관리자(`root`) 권한으로 실행되므로, Git이 소유권 불일치 경고를 발생시키지 않고 정상적으로 파일 및 브랜치 제어를 허용하게 됩니다.

---

### 4. 핵심 개념 정리

- **Git 브랜치 (Git Branch)**: 원본 소스 코드의 상태를 그대로 유지한 채, 독립적인 작업 영역을 가상으로 분기하여 새로운 기능 개발이나 버그 수정을 병렬적으로 진행할 수 있게 만드는 형상 관리 기술입니다. 메인 줄기(master)에서 뻗어 나와 서로 영향을 주지 않고 안전한 실험적 코딩을 가능케 합니다.

- **다중 사용자 저장소 보안 (Safe Directory)**: Git은 취약점 방어를 위해 현재 명령어를 실행하는 리눅스 로그인 사용자 계정과 타겟 저장소(`.git`)의 폴더 소유자가 다를 경우, 악성 스크립트 실행을 막기 위해 작업을 원천 차단하는 보안 구조를 가지고 있습니다.

💡 **비유하자면**, 회사 공용 회의실에 놓인 "비밀 금고(root 소유 저장소)"에 일반 사원인 `natasha`가 접근하려 하자, 경비원(Git 보안 엔진)이 "신원 확인이 불가능한 수상한 접근"이라며 강제로 출입을 막는 것과 같습니다. 이때 건물 마스터키를 가진 사장님 도장(`sudo`)을 찍고 들어가서 안전하게 서류(브랜치)를 결재한 상황입니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

- **리눅스 멀티테넌시 권한과 Git 보안 매커니즘의 상관관계 이해**: 시스템상에서 발생하는 `fatal: detected dubious ownership` 에러가 단순한 소프트웨어 버그가 아닌, 다중 사용자(Multi-user) 서버 환경에서 소스 코드 변조를 막기 위한 형상 관리 솔루션의 고도화된 방어 기제임을 근본 원인(RCA) 관점에서 명확히 파악했습니다.

- **권한 레이어 격리(Isolate) 해결 역량**: 보안 규정상 상위 디렉토리의 전체 권한을 변경(`chmod 777` 등)하는 위험한 방식을 지양하고, `sudo` 권한 상승을 통해 파일 시스템 컴플라이언스를 완벽하게 방어하며 미션을 완수하는 인프라 아키텍처적 유연성을 정립했습니다.
