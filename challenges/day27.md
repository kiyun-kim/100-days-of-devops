## 📅 Day 27: Git Revert Some Changes

### 1. Task

- **요구사항**: Nautilus 애플리케이션 개발 팀의 잘못된 커밋 배포 요청을 철회하기 위해, 기존의 커밋 히스토리를 파괴하지 않고 안전하게 이전 상태(`initial commit`)로 되돌리는 신규 상쇄 커밋을 생성하고 작업 트리를 정상화합니다.

- **목표**:
  1. Storage 서버(`ststor01`)의 로컬 저장소 경로 `/usr/src/kodekloudrepos/news`로 이동합니다.
  2. 최신 커밋(`HEAD`)을 초기 커밋(`initial commit`) 상태로 되돌리는 작업을 수행합니다.
  3. 새롭게 생성되는 Revert 커밋의 메시지를 규격(**`revert news`**, 전체 소문자)에 맞게 지정합니다.
  4. 커밋 전환 과정에서 발생하는 작업 트리의 잔재를 완전히 클린업하여 무결성 상태를 증명합니다.

---

### 2. Workflow

```text
[현재 HEAD: 잘못된 커밋] ──(git revert HEAD)──> [신규 커밋: revert news]
                                                   │
                                                   ▼ [누락 발생: Untracked news.txt 잔재]
                                              [git clean -fd]
                                                   │
                                                   ▼
                                      [Working Tree Clean 상태 확보]

```

---

### 3. 해결 과정 (Action)

#### 3-1. 저장소 진입 및 히스토리 분석

다중 사용자 인프라 환경의 소유권 경고(`dubious ownership`)를 차단하기 위해 `sudo` 권한을 활용하여 기존 커밋 로그를 역추적합니다.

```bash
# 배포 대상 로컬 Git 저장소 디렉토리로 이동합니다.
cd /usr/src/kodekloudrepos/news

# 현재 저장소의 커밋 히스토리와 HEAD가 가리키는 최신 커밋 해시를 확인합니다.
sudo git log --oneline

```

#### 3-2. 커밋 되돌리기(Revert) 및 규격 메시지 적용

기존의 이력을 강제로 삭제하는 `reset` 방식 대신, 안전하게 반대 변경 사항을 기록하는 `revert` 방식을 적용합니다.

```bash
# 최신 커밋(HEAD)을 되돌리는 revert 명령을 실행합니다.
sudo git revert HEAD

```

_(명령어 실행 후 자동 전환되는 vi 에디터 환경에서 기존 텍스트를 소멸시키고 명세서 규격인 `revert news`를 소문자로 정확히 기입 후 저장합니다.)_

```bash
# 커밋 히스토리를 재조회하여 'revert news' 메시지를 가진 신규 커밋이 정상 발행되었는지 검증합니다.
sudo git log --oneline

```

#### 3-3. 누락 원인 분석 및 최종 워킹 디렉토리 클린업 (Critical Section)

`revert` 완료 후 `sudo git status` 검증 과정에서 과거 커밋에 묶여있던 파일(`news.txt`)이 추적 해제(`Untracked files`) 상태로 워킹 디렉토리에 잔존하는 현상이 발견되었습니다. 강제 클린업을 단행합니다.

```bash
# 1. 워킹 디렉토리에 격리되지 않고 남아 있는 미추적 파일(news.txt)을 강제로 제거합니다.
sudo git clean -fd

# 2. 작업 트리가 완벽하게 깨끗해졌는지(nothing to commit, working tree clean) 최종 점검합니다.
sudo git status

```

### 4. 핵심 개념 정리

- **Git Revert (커밋 되돌리기)**: 특정 커밋에서 발생한 변경 사항과 정반대의 작업을 수행하는 새로운 커밋을 생성하는 기능입니다. 이력을 강제로 지워버리는 `git reset`과 달리 과거 히스토리를 고스란히 보존하므로, 협업 스트림 및 운영 인프라의 추적성을 해치지 않는 안전한 롤백 기법입니다.

  > 💡 영수증 장부에 잘못 적힌 "10만 원 지출 기록(잘못된 커밋)"을 화이트로 지워버리는 것이 아니라, 아래 줄에 "10만 원 입금/취소(Revert 커밋)"라는 반대 거래 내역을 새로 적어 넣어 최종 합계를 0원으로 맞추는 정석적인 회계 처리와 같습니다.

- **Git Clean (미추적 파일 제거)**: Git의 추적 대상에 포함되지 않은 워킹 디렉토리 내의 임시 파일이나 잔재들을 강제로 물리적 삭제하는 명령어입니다.

  > 💡 인테리어 공사(Revert 작업)가 끝난 후 방 바닥에 흩어져 있는 "건축 자재 쓰레기 및 먼지(Untracked 파일)"들을 빗자루로 깔끔하게 쓸어서 쓰레기통에 버리는 대청소 작업과 같습니다.

### 5. 무엇을 배웠는가 (Takeaway)

- **실무 관점의 의의**: 실제 엔지니어링 및 프로덕션 MLOps 환경에서는 장애 발생 시 `git reset`으로 이력을 임의 가공하는 행위는 협업 동기화 충돌을 유발하는 금기 사항입니다. 반드시 `git revert`를 통해 취소 이력 자체를 투명하게 기록해야 합니다. 이번 공정을 통해 대형 인프라 파이프라인에서의 정석적인 롤백 아키텍처 규칙을 확립했습니다.
