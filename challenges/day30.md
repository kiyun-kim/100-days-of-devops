## 📅 Day 30: Git hard reset

### 1. Task

- **요구사항**: xFusionCorp 개발 팀의 요청에 따라, 테스트 목적으로 불필요하게 적체된 최신 커밋 이력들과 워킹 트리의 파일 변경 사항들을 특정 안전 지점으로 강제 소멸(Reset)시키고, 이를 원격 저장소에 강제로 동기화 배포하여 형상 라인을 완전히 정화합니다.

- **목표**:
  1. Storage 서버(`ststor01`)의 로컬 저장소 경로 `/usr/src/kodekloudrepos/blog`로 이동합니다.
  2. 커밋 히스토리에 단 두 개의 커밋(**`initial commit`** 및 **`add data.txt file`**)만 남도록 강제 리셋을 수행합니다.
  3. 로컬의 과거 리셋 형상을 원격 원본 저장소 `/opt/blog.git`에 강제 푸시(`--force`)하여 최종 반영합니다.

---

### 2. Workflow

```text
[리셋 전 히스토리]  initial commit ── add data.txt file ── Test Commit1 ── ... ── Test Commit10 (HEAD)
                                               ▲
                                               │ [git reset --hard 383f0cf] 강제 리셋 단행
                                               │
[리셋 후 히스토리]  initial commit ── add data.txt file (HEAD, master, origin/master)
                                               │
                                               ▼ [git push origin master --force]
                                    [원격 저장소 강제 동기화 완수]

```

---

### 3. 해결 과정 (Action)

#### 3-1. 저장소 진입 및 히스토리 분석

다중 사용자 인프라 환경의 소유권 경고(`dubious ownership`)를 우회하기 위해 `sudo` 권한을 결합하여 현재 적체된 테스트 커밋 로그들을 역추적합니다.

```bash
# 배포 대상 로컬 Git 저장소 디렉토리로 이동합니다.
cd /usr/src/kodekloudrepos/blog

# 전체 커밋 히스토리를 한 줄씩 출력하여 리셋 타겟인 'add data.txt file'의 해시를 식별합니다.
sudo git log --oneline

```

_(출력 로그에서 `add data.txt file` 메시지의 고유 해시값인 `383f0cf`를 포착했습니다.)_

#### 3-2. 강제 하드 리셋(Reset --hard) 단행

지정된 커밋 해시 이후에 테스트 커밋 이력과 워킹 디렉토리 내의 파일 변경점을 완전히 물리적으로 소멸시킵니다.

```bash
# 타겟 커밋 해시(383f0cf) 지점으로 워킹 트리와 인덱스를 강제 일치시킵니다.
sudo git reset --hard 383f0cf

# HEAD 위치가 'add data.txt file' 지점으로 정상 후퇴했는지 로그를 재확인합니다.
sudo git log --oneline

```

#### 3-3. 원격 저장소 강제 배포 (Force Push)

로컬 히스토리가 원격 저장소(`origin`)의 이력보다 과거 시점으로 역행했으므로, 일반 푸시 거부 현상을 무력화하기 위해 `--force` 옵션을 인입합니다.

```bash
# 리셋된 로컬의 정화 형상을 원격 저장소에 강제로 덮어씁니다.
sudo git push origin master --force

# 최종 작업 트리 무결성과 추적 브랜치 상태가 Clean한지 교차 검증합니다.
sudo git status

```

---

### 4. 핵심 개념 정리

- **Git 하드 리셋 (Git Reset --hard)**: 지정한 특정 커밋 지점으로 현재 브랜치의 HEAD 위치를 강제 이동시키면서, 그 사이에 존재하던 모든 커밋 이력(History), 스테이징 영역(Index), 그리고 실제 작업 디렉토리(Working Directory)의 파일 변경점까지 흔적도 없이 완전히 삭제하는 파괴적 형상 관리 기술입니다.

  > 💡 아래 한글 문서나 워드에서 오타와 잘못된 내용들을 많이 작성했을 때, `Ctrl + Z`를 연타하여 문서를 수정하는 것이 아니라, 아예 안전하게 저장해 두었던 "어제 자 백업 파일(add data.txt file 커밋)"을 그대로 불러와서 오늘 편집 중이던 임시 화면과 임시 파일들을 통째로 덮어씌워 포맷하는 것과 같습니다.

- **강제 푸시 (Force Push - `--force`)**: 로컬 저장소의 커밋 이력이 원격 저장소의 최신 이력보다 뒤처져 있거나 구조가 어긋났을 때, Git의 기본 업스트림 보호 메커니즘(Fast-forward)을 우회하고 로컬의 형상으로 원격 저장소를 강제 강탈/동기화하는 명령어입니다.

  > 💡 중앙 문서고(원격 저장소)의 관리자가 **"가져오신 문서 이력이 메인 장부보다 과거 기록이라 접수할 수 없습니다"라고 거부할 때, 최고 관리자 명령서(`--force**`)를 제시하여 기존 중앙 문서고의 장부를 파쇄하고 "내 들고 온 장부(리셋된 로컬 형상)"로 강제 교체해 버리는 강력한 동기화 행위입니다.

### 5. 무엇을 배웠는가 (Takeaway)

- **실무 관점의 의의**: 프로덕션 및 기업용 인프라 관리 환경에서 무분별한 테스트용 커밋이나 잘못 반영된 구성 명세가 적체되었을 때, 이력을 깔끔하게 정리하여 소스 코드 가독성을 확보하는 정화 공정은 매우 중요합니다. 다만, `reset --hard`와 `force push`는 동료 엔지니어들의 로컬 형상 붕괴를 유발할 수 있으므로, 이번 실습처럼 철저히 격리된 테스트용 저장소 환경이나 명시적 승인이 완료된 상황에서만 제한적으로 수행해야 하는 양날의 검임을 인지했습니다.

- **구조적 사고 과정을 통한 무결성 확보**: 명령어의 성공 유무만 확인하는 주니어 단계의 단선적 작업 방식을 탈피하여, 리셋 단행 후 `git status`를 통한 작업 트리 클린업 유무, 그리고 `git log --oneline`과 `origin/master` 추적 관계 레이어를 끝까지 교차 추적함으로써, 자동 채점 봇이 요구하는 무결성 기준을 픽셀 단위로 완벽하게 충족시켜 미션을 원스톱으로 통과해 내는 방어적 엔지니어링 역량을 공고히 했습니다.
