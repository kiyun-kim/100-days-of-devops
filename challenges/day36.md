## 📅 Day 36: Deploy Nginx Container on Application Server

### 1. Task

- **요구사항**: Nautilus 애플리케이션 개발 팀의 인프라 컨테이너화 테스트 일환으로, 지정된 애플리케이션 서버에 경량화된 Nginx 웹 서버 컨테이너를 배포하고 지속적으로 서비스되도록 백그라운드 데몬 형태로 실행해야 합니다.

- **목표**:
  1. Application Server 2(`stapp02`, 계정: `steve`)에 접속합니다.
  2. 리소스 효율성을 위해 `nginx:alpine` 이미지를 기반으로 컨테이너를 생성합니다.
  3. 컨테이너의 이름을 `nginx_2`로 명명하고, 사용자 터미널 세션과 무관하게 `Up` (Running) 상태가 유지되도록 구성합니다.

---

### 2. Workflow

```text
[Client (jump-host)] ──(SSH 접속)──> [Application Server 2 (stapp02)]
                                            │
                              (docker run -d --name nginx_2 nginx:alpine)
                                            │
                                            ▼
                              [Container: nginx_2 (Status: Up / Running)]

```

---

### 3. 해결 과정 (Action)

#### 3-1. 대상 애플리케이션 서버 접속

인프라 명세서에 정의된 자격 증명을 사용하여 타겟 서버로 진입합니다.

```bash
# Application Server 2로 SSH 접속 (계정: steve)
ssh steve@stapp02
# 비밀번호 입력: Am3ric@

```

#### 3-2. 컨테이너 배포 및 백그라운드 실행

로컬에 이미지가 없을 경우 자동으로 Docker Registry에서 Pull을 수행하며, 컨테이너를 지정된 이름으로 백그라운드 실행합니다.

```bash
# alpine 태그를 가진 nginx 이미지를 기반으로 nginx_2 컨테이너를 백그라운드(-d)에서 실행
sudo docker run -d --name nginx_2 nginx:alpine

```

#### 3-3. 컨테이너 상태 검증

프로세스가 포그라운드 점유 없이 백그라운드에서 정상적으로 데몬화되어 동작 중인지 확인합니다.

```bash
# 실행 중인 컨테이너 목록 중 nginx_2의 상태(Up) 점검
sudo docker ps | grep nginx_2

```

---

### 4. 핵심 개념 정리

- **Docker Run `-d` (Detached 모드)**: 컨테이너를 백그라운드에서 실행하고 터미널의 제어권을 사용자에게 즉시 반환하는 옵션입니다. 웹 서버나 데이터베이스처럼 지속적으로 동작해야 하는 서비스 데몬을 띄울 때 필수적으로 사용됩니다.

  > 💡 식당에서 요리사(컨테이너)에게 "주방에서 계속 요리해 주세요"라고 지시한 뒤, 매니저(사용자)는 즉시 홀로 나와 다른 업무를 볼 수 있게 하는 것과 같습니다. 만약 `-d` 옵션을 주지 않으면 매니저가 주방에 갇혀 요리사만 계속 쳐다보고 있어야 합니다(터미널 점유).

- **Alpine Linux Image (`:alpine`)**: 보안, 단순성, 리소스 효율성에 초점을 맞춘 5MB 내외의 초경량 리눅스 배포판인 Alpine 기반의 Docker 이미지입니다.
  > 💡 출장을 갈 때 무거운 대형 캐리어(일반 OS 이미지) 대신, 꼭 필요한 세면도구와 옷 한 벌만 챙겨서 기동성을 극대화한 '초경량 기내용 배낭'과 같습니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

- **실무적 페인 포인트(Pain Point)**: 도커를 처음 접할 때 가장 흔하게 하는 실수 중 하나가 `-d` 옵션을 누락하는 것입니다. 터미널 창에 Nginx 접속 로그가 화려하게 올라오는 것을 보고 '잘 구동되었구나' 안심한 뒤, 무심코 `Ctrl + C`를 누르거나 SSH 세션을 종료하는 순간 컨테이너도 함께 죽어버립니다. 실제 프로덕션 환경에서 웹 서버를 포그라운드로 띄웠다가 세션 단절로 서비스 장애를 유발하지 않으려면, 컨테이너의 생명주기와 세션을 분리하는 Detached 모드의 개념을 숨 쉬듯 자연스럽게 적용해야 합니다.

- **회고(Retrospective)**: 이번 미션에서 일반 `nginx:latest` 대신 굳이 `nginx:alpine`을 명시적으로 요구한 점이 인상 깊었습니다. 실무 클라우드 환경에서는 컨테이너 이미지의 크기가 곧 배포 파이프라인의 속도(Pull Time)와 스토리지 비용으로 직결되며, 불필요한 패키지가 없으므로 보안 취약점(Attack Surface)도 대폭 감소합니다. 단순히 "컨테이너를 실행할 줄 안다"를 넘어, 베이스 이미지를 최적화하여 인프라의 군살을 빼는 것이 프로페셔널한 클라우드 아키텍트의 기본 소양임을 다시 한번 되새기게 되었습니다.
