## 📅 Day 37: Copy File to Docker Container

### 1. Task

- **요구사항**: Nautilus DevOps 팀의 보안 지침에 따라, App Server 2(Docker 호스트)에 보관된 기밀 데이터 파일(`/tmp/nautilus.txt.gpg`)을 현재 백그라운드에서 실행 중인 `ubuntu_latest` 컨테이너 내부의 특정 경로(`/home/`)로 원본 훼손 없이 복사해야 합니다.

- **목표**:
  1. App Server 2(`stapp02`, 계정: `steve`)에 접속합니다.
  2. `docker cp` 명령어를 활용하여 호스트 시스템의 암호화된 기밀 파일을 컨테이너 내부로 전달합니다.
  3. `docker exec` 명령어를 통해 파일이 정상적으로 복사되었는지 무결성을 검증합니다.

---

### 2. Workflow

```text
[Docker Host: stapp02]                     [Container: ubuntu_latest]
/tmp/nautilus.txt.gpg                           /home/
          │                                        ▲
          └─────────── (docker cp) ────────────────┘
                                                   │
                              (docker exec ls -l) ─┘ (복사 결과 검증)

```

---

### 3. 해결 과정 (Action)

#### 3-1. 대상 애플리케이션 서버 접속

인프라 명세서에 정의된 자격 증명을 사용하여 파일이 위치한 호스트 서버로 진입합니다.

```bash
# App Server 2로 SSH 접속 (계정: steve)
ssh steve@stapp02
# 비밀번호 입력: Am3ric@

```

#### 3-2. 대상 컨테이너 상태 점검

파일을 주입할 대상 컨테이너가 정상적으로 동작(`Up`) 중인지 확인합니다. 컨테이너가 중지된 상태라도 복사는 가능하지만, 실무적 관점의 상태 확인을 선행합니다.

```bash
# ubuntu_latest 컨테이너 동작 상태 확인
sudo docker ps | grep ubuntu_latest

```

#### 3-3. 호스트 파일을 컨테이너 내부로 복사

볼륨(Volume) 마운트 없이 구동 중인 컨테이너의 격리된 파일 시스템 내부로 호스트의 파일을 직접 주입합니다.

```bash
# 호스트의 /tmp/nautilus.txt.gpg 파일을 컨테이너의 /home/ 경로로 복사
sudo docker cp /tmp/nautilus.txt.gpg ubuntu_latest:/home/

```

#### 3-4. 주입 결과 및 무결성 검증

컨테이너 내부에 셸 명령어를 찔러넣어 파일이 누락이나 변형 없이 정상적으로 떨어졌는지 교차 검증합니다.

```bash
# 컨테이너 내부의 /home/ 경로를 ls 명령어로 조회하여 복사된 파일 확인
sudo docker exec ubuntu_latest ls -l /home/

```

---

### 4. 핵심 개념 정리

- **`docker cp` (Container Copy)**: 컨테이너와 호스트 파일 시스템 간에 파일이나 디렉터리를 복사하는 명령어입니다.

  > 💡 이미 출항해서 바다 위에 떠 있는 배(컨테이너)를 항구로 다시 부르지 않고, 헬기(docker cp)를 띄워 필요한 화물이나 긴급 서류를 갑판 위에 정확히 투하하는 것과 같습니다.

- **`docker exec` (Execute)**: 실행 중인 컨테이너 내부에 임시로 접속하거나, 특정 셸 명령(예: `ls`, `cat`)을 전달하여 그 결괏값만 호스트 터미널로 받아보는 디버깅 목적의 핵심 명령어입니다.

---

### 5. 무엇을 배웠는가 (Takeaway)

- **볼륨 마운트 없이 돌아가는 컨테이너에 긴급 패치하기**: 실무를 하다 보면, 이미 프로덕션 환경에 띄워진 컨테이너에 인증서(.gpg, .pem)나 설정 파일(.conf) 하나를 긴급하게 덮어씌워야 할 때가 있습니다. 이럴 때마다 컨테이너를 내리고 이미지를 다시 빌드하는 것은 치명적인 서비스 다운타임을 유발합니다. 이번 실습을 통해 `docker cp`가 무중단 상태에서 파일을 찔러넣을 수 있는 훌륭한 '응급처치 킷'이라는 점을 체감했습니다.

- **맹목적인 복사가 부르는 대참사 방지**: 파일을 밀어 넣은 뒤 `Successfully copied...` 로그만 보고 '성공했겠지' 하며 넘어가면, 컨테이너 내부의 권한(Permission) 꼬임이나 경로 오타로 인해 애플리케이션이 뻗어버리는 페인 포인트를 겪기 쉽습니다. 이번 과정에서 `docker exec`를 이용해 목적지에 파일이 1바이트의 오차도 없이 정확히 떨어졌는지 직접 눈으로 확인(`ls -l`)하는 과정을 거치며, "아마도 잘 들어갔을 겁니다"라는 막연한 추측을 "검증까지 마쳤습니다"라는 프로페셔널한 확신으로 바꾸는 엔지니어링 습관의 중요성을 배웠습니다.
