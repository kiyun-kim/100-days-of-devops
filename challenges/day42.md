## 📅 Day 42: Docker Macvlan 네트워크 구축을 통한 물리 네트워크 대역 독립화

### 1. Task

- **요구사항**: 다양한 컨테이너화된 애플리케이션들이 기존 호스트의 가상 브릿지를 거치지 않고, 외부 물리 네트워크 인터페이스와 직접 결합하여 고유한 MAC 주소 및 IP 대역을 할당받을 수 있도록 고성능 Macvlan 네트워크 환경을 사전 구축합니다.

- **목표**: Stratos DC 내부의 Application Server 1 환경에 접근하여 특정 서브넷 범위를 활용하는 물리 지향형 가상 네트워크를 생성하고 검증합니다.
  1. 대상 서버인 App Server 1 (`stapp01`)에 SSH 원격 접속을 수행합니다.
  2. 드라이버 형식을 `macvlan`으로 지정하여 컨테이너-호스트 간 네트워크 가상화 계층을 우회하도록 구성합니다.
  3. 네트워크 식별 명칭을 `media`로 선언합니다.
  4. 서브넷 대역(`192.168.0.0/24`) 및 IP 할당 범위(`192.168.0.0/24`)를 엄격하게 제한하여 네트워크를 생성합니다.

---

### 2. Workflow

```text
  [ Jump Host ]
        │
        │ (SSH / tony)
        ▼
  [ App Server 1 (stapp01) ]
        │
        ├── [ Docker Daemon ]
        │         │ (Docker Network Engine)
        │         └─ Create: `media`
        │
        └── [ macvlan Driver Bind ] ── [ Physical NIC Bridge ]
                  │
                  ├── Subnet: 192.168.0.0/24
                  └── IP Range: 192.168.0.0/24

```

---

### 3. 해결 과정 (Action)

#### 3-1. App Server 1 원격 접속 및 인프라 제어 권한 확보

작업 대상인 App Server 1(`stapp01`)에 엔지니어 계정으로 안전하게 접근합니다.

```bash
# Jump Host에서 App Server 1 서버로 SSH 원격 접속 실행
ssh tony@stapp01

```

#### 3-2. Macvlan 네트워크 엔진 구성 및 대역 할당

정의된 네트워크 구조 설계에 맞추어 `macvlan` 드라이버 옵션과 네트워크 자원 정보를 포함한 생성 명령을 수행합니다.

```bash
# 지정된 서브넷 및 IP 범위를 정의하여 macvlan 드라이버 기반의 media 네트워크 생성
sudo docker network create -d macvlan \
  --subnet=192.168.0.0/24 \
  --ip-range=192.168.0.0/24 \
  media

```

#### 3-3. 네트워크 구성 상태 및 메타데이터 무결성 검증

생성된 자원이 도커 데몬에 올바르게 바인딩되었는지 전체 목록 및 상세 명세(Inspect) 기능을 통해 최종 검토합니다.

```bash
# Docker 네트워크 엔진 내 활성화된 네트워크 목록 조회
sudo docker network ls

# 생성된 media 네트워크의 서브넷, IP 범위, 드라이버 형식 상세 설정값 검증
sudo docker network inspect media

```

### 4. 핵심 개념 정리

- **Macvlan 드라이버**
  - **전문 정의**: 컨테이너의 가상 네트워크 인터페이스를 호스트의 물리 네트워크 인터페이스와 하드웨어 수준에서 직접 매핑하여, 가상 브릿지를 거치지 않고 실제 물리 스위치로부터 고유한 MAC 주소와 독립적인 IP를 할당받을 수 있게 지원하는 가상 네트워크 드라이버입니다.

  > 💡 비유하자면, 대형 아파트 단지(호스트)의 공동 우편함(Bridge)을 거쳐 편지를 전달받는 대신, 각 호실(컨테이너)마다 대문 앞에 외부 도로와 직접 연결되는 개별 우체통(물리 MAC 주소 및 IP)을 만들어 우체부와 직거래를 하는 것과 같습니다.

- **Subnet (서브넷)**
  - **전문 정의**: 거대한 하나의 네트워크 대역을 효율적으로 관리하고 보안 영역을 격리하기 위해 논리적으로 쪼개어 놓은 중소규모의 서브 네트워크 단위이자 경계면입니다.

  > 💡 비유하자면, 광활한 토지 대장 위에 '이 구역은 42번가 행정구역이다'라고 가상의 경계선을 굵은 펜으로 확실하게 그어 구분해 놓는 주소 구획 정리 작업과 같습니다.

- **IP Range (IP 할당 범위)**
  - **전문 정의**: 서브넷 네트워크 내에서 Docker 컨테이너가 생성될 때 동적으로 고유 IP 주소를 부여받아 실제로 사용할 수 있도록 사전에 약속해 놓은 특정 주소 범위 공간입니다.

  > 💡 비유하자면, 새로 분양한 행정구역(Subnet) 안에서 실제로 주민들이 분양받아 집을 짓고 문패를 달 수 있도록 시청에서 허가해 준 '실제 건축 허가용 필지 번호 범위'와 같습니다.

### 5. 무엇을 배웠는가 (Takeaway)

- **회고(Retrospective)**: 가상 브릿지 기반의 `bridge` 네트워크에만 의존하던 기존 방식에서 탈피하여 물리 대역에 컨테이너를 직접 연결하는 `macvlan` 구조를 실습해 봄으로써, 컨테이너 환경의 네트워크 설계 자유도가 한 단계 더 넓어짐을 체감했습니다. 이 구성을 미리 다뤄보지 않았다면 나중에 패킷 캡처나 대용량 트래픽 처리 장비를 구현할 때 호스트 네트워크 병목 현상으로 큰 낭패를 보았을 것입니다.

- **Pain Point**: 이러한 물리 연동형 네트워크 인프라 구축 작업을 수동으로 처리하게 되면, 도메인 주소 오타나 서브넷 마스크 기입 오류 같은 사소한 휴먼 에러 하나로 전체 IDC 네트워크에 충돌(IP Conflict)을 야기하는 대형 장애로 이어질 수 있습니다. 향후에는 네트워크 주소 할당 프로세스도 코드로 관리하는 IaC 파이프라인으로 자동화하여 사전에 충돌 여부를 검증하는 로직이 필연적으로 수반되어야 함을 배울 수 있었습니다.

- **성장 포인트**: 앞으로 애플리케이션의 성능 요구사항 및 통신 구조에 따라 단순히 기본 설정만을 고집하지 않고, 하드웨어 성능을 최대로 끌어올릴 수 있는 다양한 네트워크 드라이버의 특성을 면밀히 파악하여 아키텍처를 제시하는 다각적 관점의 프로페셔널 엔지니어로 성장하게 되었습니다.
