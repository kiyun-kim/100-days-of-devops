## 📅 Day 44: Docker Compose를 활용한 Apache(httpd) 웹 서버 배포 및 볼륨 바인딩

### 1. Task

- **요구사항**: Nautilus 애플리케이션 개발 팀의 정적 웹사이트 콘텐츠 호스팅 요청에 대응하여, Docker Compose 기반으로 `httpd` 웹 서버를 독립적으로 배포하고 외부 포트 및 호스트 볼륨 매핑을 신속하게 처리합니다.

- **목표**: Stratos DC 내부의 Application Server 2 (`stapp02`) 환경에 접근하여 지정된 볼륨과 포트 구성을 완전하게 충족하는 컨테이너 환경을 코드로 선언하여 배포합니다.
  1. 대상 서버인 App Server 2 (`stapp02`)에 SSH 원격 접속을 수행합니다.
  2. `/opt/docker/docker-compose.yml` 경로에 명세에 맞춘 Compose 구성 파일을 생성합니다.
  3. 안정성이 확보된 최신 버전의 Apache `httpd` 이미지를 명시하고, 컨테이너 식별명을 `httpd`로 단일화합니다.
  4. 호스트의 `5003` 포트를 컨테이너 내부의 `80` 포트로 매핑하고, 호스트의 기존 데이터 볼륨인 `/opt/security`를 컨테이너의 정적 루트 경로인 `/usr/local/apache2/htdocs`에 직접 마운트합니다.

---

### 2. Workflow

```text
  [ External Traffic ]
          │ (TCP Port 5003)
          ▼
  [ App Server 2 (Host: stapp02) ]
          │
          ├── [ Directory: /opt/docker ]
          │         └── File: docker-compose.yml (Configuration)
          │
          ├── [ Port Map ] ─── 5003 (Host) : 80 (Container)
          └── [ Volume Map ] ─ /opt/security (Host) : /usr/local/apache2/htdocs (Container)
                    │
                    ▼
        [ Container: httpd (httpd:latest) ]

```

---

### 3. 해결 과정 (Action)

#### 3-1. App Server 2 원격 접속 및 작업 경로 준비

인프라 관리 대상 서버인 App Server 2에 원격 접속을 수행한 후, 선언적 환경 정의를 위한 Docker 전용 작업 경로를 생성하고 이동합니다.

```bash
# Jump Host에서 App Server 2 서버로 SSH 원격 접속 실행
ssh steve@stapp02

# Docker 구성 파일을 중앙 집중식으로 관리하기 위한 디렉터리 생성 및 경로 이동
sudo mkdir -p /opt/docker
cd /opt/docker

```

#### 3-2. `docker-compose.yml` 파일 설계 및 영속성 설정

요청받은 구조적 조건들을 만족하도록 야믈(YAML) 형식의 컨테이너 배치 설정 명세서를 작성합니다.

```bash
# 작업 디렉터리 내부에서 docker-compose.yml 파일 편집 실행
sudo vi docker-compose.yml

```

```yaml
version: '3.8'

services:
  web:
    image: httpd:latest
    container_name: httpd
    ports:
      - '5003:80'
    volumes:
      - /opt/security:/usr/local/apache2/htdocs
```

- **설정 변경 의도**: 다중 배포 및 구성 형상 관리에 용이하도록 서비스를 정의하였습니다. 호스트 서버의 외부 인입용 `5003` 포트를 차단 없이 내부 Apache 기본 웹 포트 `80`과 논리적으로 가교하였고, 호스트 환경에 보존되어 있던 비즈니스 정적 데이터 자원인 `/opt/security` 경로를 웹 서버의 콘텐츠 송출 경로인 `/usr/local/apache2/htdocs`에 바인드 마운트하여 데이터의 정합성과 영속성을 확보했습니다.

#### 3-3. Docker Compose 엔진을 이용한 단일 백그라운드 구동

지정한 YAML 아키텍처 설계를 기반으로 무결한 기동 명령을 실행합니다.

```bash
# 정의된 Compose 명세에 맞추어 컨테이너 서비스를 생성하고 백그라운드 환경에 영구 기동
sudo docker compose up -d

```

#### 3-4. 구동 상태 및 데이터 마운트 무결성 확인

실제 프로세스의 구동과 호스트 하드웨어 네트워크 포트, 볼륨 마운트 매핑 지점이 정확하게 상호 바인딩되었는지 최종 확인합니다.

```bash
# httpd 컨테이너의 업타임 및 활성화된 바인드 포트(5003) 확인
sudo docker ps | grep httpd

# 호스트 스토리지와 컨테이너 스토리지의 디렉터리 간 바인드 마운트 상세 매핑 관계 최종 정밀 검증
sudo docker inspect httpd --format='{{json .Mounts}}'

```

### 4. 핵심 개념 정리

- **Docker Compose (도커 컴포즈)**: 단일 또는 다중 컨테이너 애플리케이션의 환경을 하나의 YAML 파일 안에 명시적, 선언적으로 코딩하고 통합적인 컨테이너 구동, 네트워크, 스토리지 바인딩을 원클릭으로 조율할 수 있도록 지원하는 오케스트레이션 도구입니다.

  > 💡 비유하자면, 가구를 설치할 때 배송 기사에게 소파 위치, 옷장 방향을 올 때마다 매번 입으로 일일이 가이드하는 대신, 방의 전체적인 구조를 입체적으로 그려놓은 도면(YAML) 한 장을 건네주고 "이대로 설치해 주십시오"라고 명확히 지시하는 설계도와 같습니다.

- **Bind Mount (바인드 마운트)**: 호스트 운영체제(OS)의 특정 디렉터리나 물리 파일 경로를 컨테이너 내부의 특정한 경로로 직접 매핑하여 상호 간 실시간 파일 시스템 자원을 공유하며, 컨테이너의 파괴와 재생성 주기와 무관하게 데이터를 호스트에 영구적으로 보호하는 데이터 보존 기술입니다.

  > 💡 비유하자면, 이동식 조립 텐트(컨테이너)의 한쪽 벽면에 창을 뚫어, 텐트 바깥에 놓인 거대하고 견고한 돌 선반(/opt/security)을 텐트 안에서도 마치 내부 탁자처럼 직접 만질 수 있도록 벽체 구조를 정확하게 맞물려 고정해 놓은 것과 같습니다.

- **httpd (Apache HTTP Server 데몬)**: 전 세계 엔터프라이즈 환경에서 강력한 호환성과 신뢰성을 인정받은 오픈소스 웹 서버 프로그램으로, 클라이언트의 HTTP 요청 규격에 반응하여 가공되지 않은 정적인 웹 문서 리소스(HTML, CSS, 이미지 등)를 정확하게 전달하도록 특화된 서비스 데몬입니다.

  > 💡 비유하자면, 고객이 매장에 들어와 메뉴판을 요구할 때 주방에서 복잡하게 음식을 조리할 필요 없이 미리 출력되어 인쇄된 팜플릿 상자를 즉석에서 깔끔하게 꺼내 건네주는 신속한 카운터 전담 안내 직원과 같습니다.

### 5. 무엇을 배웠는가 (Takeaway)

- **회고(Retrospective)**: 매번 긴 인자값과 일회성 옵션을 수동으로 수십 자씩 작성하며 에러를 유발하던 `docker run` 커맨드 위주의 기동 방식에서 벗어나, 파일 하나에 설계를 이식하는 Docker Compose를 실제 업무에 활용함으로써 인프라 구성의 간결함과 예측 가능성을 깊게 체감했습니다. 이 방식을 체득하지 않았다면 컨테이너가 롤백되거나 재생성될 때마다 환경 설정을 기억하고 재구성하기 위해 막대한 리소스를 낭비했을 것입니다.

- **Pain Point**: 실무 운영 환경에서 디렉터리 바인딩 경로를 타이핑하는 과정은 휴먼 에러의 가장 빈번한 원인이 됩니다. 만약 `/opt/security`와 같이 중요한 보안 및 웹 정보가 미리 저장된 호스트 디렉터리를 가공 없이 연결하는 상황에서 단 한 글자의 타이핑 실수라도 발생하면, 컨테이너 내부에서는 빈 디렉터리를 띄워 웹 페이지가 비정상 노출되거나 기존 자원이 은폐되는 치명적인 업무 중단 장애를 초래합니다. 코드 기반으로 선언된 자산(YAML)을 점검하고 보존하는 과정이 장애 발생 가능성을 구조적으로 원천 차단한다는 가치를 확실히 실감했습니다.

- **성장 포인트**: 단순한 테스트 컨테이너 배포를 넘어, 인프라의 형상을 명확하게 코드화(IaC)하여 보존하는 기초적인 형상 통제 역량을 다지게 되었습니다. 향후 다른 엔지니어와의 협업이나 인수인계 상황 시, 길고 모호한 가이드북 대신 이 깔끔한 Compose 명세서 단 한 장만 전달하더라도 어느 환경에서나 100% 동일한 상태의 아키텍처를 안정적으로 가동할 수 있는 더 성숙하고 수준 높은 인프라 전문가로 성장하는 발판이 되었습니다.
